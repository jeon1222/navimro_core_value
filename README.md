# NAVIMRO Core Value v4 - 반기 추세 / Render PostgreSQL 운영본

약 130명이 Render URL로 참여하고, 매년 상반기/하반기 2회 반복하여 추세를 보는 운영을 기준으로 만든 버전입니다.

## 핵심 구조
- PostgreSQL `participants`: 직원 명단
- PostgreSQL `diagnosis_periods`: 진단 기간 (예: 2026년 상반기, 2026년 하반기)
- PostgreSQL `core_value_results`: 직원 + 진단기간별 핵심가치 결과
- 결과 고유 기준: `participant_id + period_id`
- 같은 반기에서 다시 진단하면 그 반기 결과만 최신 결과로 갱신
- 다른 반기의 과거 결과는 그대로 유지
- 에티켓 응답/점수는 서버/DB에 저장하지 않음

## 직원 화면
1. 성명 직접 입력 + 사번 직접 입력으로 본인확인
2. 현재 활성 진단기간 표시
3. 현재 반기 진단 실시
4. 결과 화면에서
   - 이번 반기 결과
   - 전체 결과 / 추세
5. 전체 보기에서는 반기별 총점 변화와 각 기간의 유형, OF/RP/CS/LE 축 점수를 확인

직원은 성명과 사번으로 본인확인한 뒤 `내 결과 / 추세 보기`로 과거 결과를 다시 확인할 수도 있습니다.

## 관리자 화면
### 진단 기간
- 년도 + 상반기/하반기 생성
- 생성과 동시에 현재 활성 기간으로 설정 가능
- 기존 기간 버튼을 눌러 다시 활성화 가능

## 직원 명단 Excel
첫 번째 시트 헤더:
- 팀명 (필수)
- 성명 (필수)
- 사번 (필수)

사번은 고정 식별키로 사용합니다. 업로드 시 사번 원문은 DB에 저장하지 않고 `EMPLOYEE_ID_HMAC_SECRET`을 이용한 HMAC-SHA256 값만 저장합니다. 팀 이동 후 새 명단을 업로드해도 같은 사번이면 과거 결과와 연결됩니다.

```powershell
$env:ADMIN_KEY="change-me"

```

## Render 배포
이 폴더 전체를 GitHub 저장소 루트에 올린 후 Render Blueprint로 배포할 수 있습니다.

`render.yaml` 기본값:
- Region: Singapore
- Web Service: free
- PostgreSQL: free
- `DATABASE_URL`: Render PostgreSQL 자동 연결
- `ADMIN_KEY`: Render 생성 과정에서 직접 입력
- `EMPLOYEE_ID_HMAC_SECRET`: 사번 HMAC용 비밀키. 32자 이상의 길고 랜덤한 값을 사용하고, 운영 중에는 변경하지 마세요.

무료 Web Service는 유휴 시 sleep될 수 있어 첫 접속이 느릴 수 있습니다. 행사 중 항상 즉시 열려야 한다면 Web Service plan만 유료 compute로 변경할 수 있습니다.

무료 Render PostgreSQL은 현재 1GB 및 생성 후 30일 만료 제한이 있으므로, 반기 행사가 끝나면 관리자 Excel 다운로드로 결과를 반드시 별도 백업하세요.

## Render 운영 확인
배포 후 관리자 메뉴에서 반드시 다음을 확인하세요.

```text
저장 방식: PostgreSQL
현재 활성 기간: 2026년 하반기 (예시)
등록 직원: 130
```

`저장 방식: JSON`이면 Render PostgreSQL이 연결되지 않은 상태이므로 실제 배포 전에 수정해야 합니다.

## 개인정보/운영 참고
- 일반 직원 화면에는 직원 명단 API를 제공하지 않습니다. 팀명·성명·완료여부·participant ID 목록을 브라우저로 내려주지 않습니다.
- 관리자 API에도 사번 원문을 반환하지 않습니다. 사번은 등록 여부만 확인할 수 있고, 세부 문항 응답은 관리자만 조회합니다.
- 직원 본인확인은 `성명 직접 입력 + 사번 직접 입력`으로 처리하며, 서버에서 성명과 입력 사번의 HMAC을 함께 검증합니다.
- `ADMIN_KEY`는 GitHub에 직접 적지 말고 Render Environment Secret으로 관리하세요.


## v5 변경사항
- 직원 진입: 성명 입력 → 사번 입력 → 서버 본인확인
- 사번 원문은 공개 API와 관리자 API에 노출하지 않으며 PostgreSQL의 `participants.employee_id_hash`와 서버에서 HMAC 비교합니다.

- 전체 누적 화면에서 반기별 총점 추세와 각 반기 유형/4개 축 결과를 함께 볼 수 있습니다.

- S 안정개선형 설명에서 C 성향을 상대적으로 낮게 보이게 할 수 있는 비교 표현을 제거하고 중립적으로 정리했습니다.
- ORSE 성장경로의 `리더형 오너` 표현을 제거해 특정 유형이나 성장 방향이 상위 단계처럼 보이지 않도록 조정했습니다.
- FRCL 블라인드스팟에서 축 정의로 직접 뒷받침되지 않는 `관계가 편한 사람 중심` 추정을 제거했습니다.
- FRSL 결과 총평의 어색한 문장 표현을 교정했습니다.
- FRCL 미어캣 이미지 미표시 시 fallback이 비버로 보이던 오류를 중립적인 동물 발자국 표시로 수정했습니다.
- 16유형 핵심키워드, 유형명, 동물 매핑, 점수 로직, 문항 및 저장 구조는 변경하지 않았습니다.
- 이 버전을 문구·맥락 기준 최종 동결본으로 사용합니다.


## v39 — 직원 본인확인 보안 강화
- 일반 직원 인증 화면에서 팀명 선택과 직원명 선택목록을 제거했습니다.
- 직원은 `성명 + 사번`을 직접 입력해 본인확인합니다.
- 공개 `/api/participants` 명단 API를 제거하고, 일반 화면에는 활성 진단기간 정보만 제공합니다.
- 서버는 사번 HMAC 일치와 성명 일치를 함께 확인한 뒤에만 해당 직원의 팀명/성명/participant ID/현재반기 완료여부를 반환합니다.
- 인증 실패 문구는 `성명 또는 사번이 일치하지 않습니다.`로 통일해 어느 항목이 틀렸는지 노출하지 않습니다.
- 동일 IP·성명 조합에서 10분 내 5회 인증 실패 시 잠시 재시도를 제한합니다.
- 명단 Excel의 `팀명 / 성명 / 사번` 구조, 관리자 팀별 집계, 과거 결과 연결, 사번 HMAC 저장방식은 그대로 유지합니다.
